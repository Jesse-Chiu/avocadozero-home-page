一、注意事项

严格按照考试要求建文件夹、命名文件夹、命名程序、保存程序！

  1. 文件名（程序名和输入输出文件名），必须使用英文小写。

  2. C/C++ 中函数 main() 的返回值类型必须是 int，程序正常结束时的返回值必须是 0；评测系统是 Linux 环境，如果没有 return 0 会返回错误。

  3. 考试环境升级到了 C++14，gets() 不能用了，使用 cin.getline() 替换。

    平时做题要养成好习惯：努力提高首次提交的正确率。

  4. 不能定义和引入头文件中系统函数同名的全局变量，否则会爆 0 分。高危变量名：dfs、next、search、index、pow（幂函数）、min、max、y1、x0、link、map、pipe、ws 等。
    规避方法：将原单词缩写，或者加下划线，例如 ma、mi、ne 等。

  5. cpp 程序"文件名"不符合要求：部分电脑默认隐藏扩展名，选手容易把文件命名成 xx.cpp.cpp，务必设置显示文件扩展名。

    • Windows 7：

      1. 打开任意文件夹
      2. 点击左上角「组织」→「文件夹和搜索选项」
      3. 切换到「查看」选项卡
      4. 取消勾选「隐藏已知文件类型的扩展名」
      5. 点击「确定」

    • Windows 10：

      1. 打开任意文件夹
      2. 点击顶部「查看」选项卡
      3. 勾选「文件扩展名」（显示/隐藏区域）
      4. 或：「查看」→「选项」→「查看」选项卡 → 取消勾选"隐藏已知文件类型的扩展名"

    • Windows 11：

      1. 打开任意文件夹
      2. 点击顶部「查看」→「显示」
      3. 勾选「文件扩展名」
      4. 或：「查看」→「显示」→「显示文件扩展名」

  6. 使用 cin/cout 时，不要再混用 scanf/printf。C++ 的 cin/cout 和 C 的 scanf/printf 是两套独立的 I/O 系统，混用可能导致输出顺序错乱、缓冲区冲突。加速写法（仅在 main 函数开头写一次）：

    ios::sync_with_stdio(false);
cin.tie(0);
cout.tie(0);

    关闭同步后，cin/cout 速度接近 scanf/printf；但关闭后绝对不能再混用 scanf/printf，否则会出问题。使用 freopen 时这两行仍然有效。

二、基本原则

核心原则：拿分、拿分、拿分，尽可能在有限的时间内多拿分！

  1. 考试的目的是拿分，一道题实在没有更好的方法，可以暴力求解或者针对部分数据点拿分。
  2. 会做的题目尽可能拿满分，先做有把握的题；不会做的题目针对部分数据点拿部分分数，不要因为一道题消耗太多时间，注意时间分配。

  3. 针对部分数据点拿分：如果对优化算法没有把握，且分析题意发现部分数据可以直接暴力求解：

    if(数据量不大的情况){
    暴力求解;
}else{
    优化求解;
}

三、考试流程注意

  1. 考前调节心态，充分自信，自信并认真是最好的考试状态。

  2. 开考：

    1. 按要求创建、命名文件夹和文件，写好基本模板；
    2. 遇到任何规则上不清楚的问题（比如保存文件、文件夹等问题）一定要和监考老师确认；

    基础模板：

    #include <bits/stdc++.h>
using namespace std;
int main() {
    freopen("题目要求的名字.in", "r", stdin);
    freopen("题目要求的名字.out", "w", stdout);
    // 代码内容
    fclose(stdin);
    fclose(stdout);
    return 0;
}
    1. 大致浏览试卷，优先做相对简单、自己有思路的题目。
  3. 快结束的前 5~10 分钟：认真检查文件夹命名、文件保存，检查每道题基本模板正确，没有多余输出。

注意：进入考场前，知识储备决定成绩；进入考场后，心态、做题习惯、做题技巧决定成绩。

四、做一个题目的流程

1. 读题

  1. 仔细阅读题目的每一句话，确认理解无误；
  2. 测试数据能人工计算的，通过计算确认理解正确；题目不明确时，通过测试数据加深理解；
  3. 自己举例计算，思考是否存在特殊情况（部分题目的特殊情况不会在样例中展现）。

2. 构建算法

  1. 仔细读题、认真思考，不要过早编程；选错方法或理解错题导致的时间浪费非常可惜。
  2. 确认数据量，判断是否要用 long long（相加、相乘是否会超 int 范围）；
  3. 确认数据范围，评估算法时间是否超限；没有更好算法时，也可以用现有思路拿部分分数。
  4. 考虑特殊边界情况。
  5. 构建算法可能耗时，但好的算法实现起来往往更简单。

十年竞赛一场空，没写 long long 见祖宗！

3. 编程

复杂问题注意划分子任务，逐步验证。

4. 调错

  1. 静态找错：先通读代码，不要上来就测样例，防止样例正确但程序存在隐藏错误。
  2. 测试样例：样例正确也可能拿不到满分，甚至 0 分；要做输出调错、单步调试。
  3. 反复举例验算：通过测试数据和自造数据验证正确性。

5. 离开题目前的检查

检查文件名、文件保存目录、freopen 编写、是否有多余输出等细节，反复确认无误后保存，再做下一题。

总结做题流程：

  1. 仔细读题
  2. 算样例，思考是否有特殊情况
  3. 构建算法：确认数据量、数据范围
  4. 逐步编程
  5. 静态读代码、测试样例、反复举例验算
  6. 检查文件名，排查多余输出

五、注意爆零情况

1. 数组爆零

（1）开大爆零

解决方法：数组定义要小于空间限制。查看数组占用空间（单位：M）：

printf("%.3lf M\n",(double)sizeof(arr)/(1<<20));

参考大小：

数组定义占用空间
int arr1[1e6]3.815 M
int arr2[1e7]38.147 M
int arr3[1e8]381.470 M
long long arr4[1e6]7.629 M
long long arr5[1e7]76.294 M
long long arr6[1e8]762.939 M

（2）开小"防爆"

看清题目数据范围，数组开小会导致越界，引发运行错误（RE）。

2. 竞赛基本数据常识

  • int 上限：$2^{31}-1$（约 21 亿，10 位整数）
  • long long 上限：$2^{63}-1$（19 位整数）
  • 1 秒循环上限：约 $10^8$ 次
  • 数组大小一般控制在 $10^6$ 量级
  • 数据量 $10^5$ 及以上，尽量用 scanf / printf 替代 cin / cout 提升效率
  • 数组尽量不要定义在函数内部（栈空间上限小，约 $10^6$），建议定义为全局变量。

六、不同平台的兼容性问题

考试机是 Windows 系统，但最终评测是 Linux 系统，GCC 标准不同，会带来兼容性问题：

  1. Windows 下结构体内的数组一般默认初始为 0，但 Linux 下包括全局变量都不会自动初始化，必须手动初始化。
  2. Windows 下 scanf 读入 long long 用 %I64d，Linux 下用 %lld；数据量小时推荐用 cin/cout，兼容性更强。
  3. Windows 下程序末尾可以不写 return 0;，但 Linux 下必须写，否则会 0 分。

七、Linux 环境

  1. 桌面建立文件夹，以自己的参赛号命名。
  2. 在新建文件夹下，建立以考题命名的四个文件夹。
  3. 分别在考题文件夹下建立对应命名的 .cpp 文件，路径不能带中文，Code::Blocks 无法识别中文路径。
  4. 运行测试代码，不要忘记添加 freopen 文件重定向。
  5. 删除测试产生的多余文件（如 .in、.out），只保留 .cpp 文件（按监考老师要求执行）。
  6. 等待老师拷贝代码时，切记不要关机，否则文件可能丢失。
  7. NOI Linux 2.0 提供计算器、日期等软件，可以使用。
  8. 考场上任何问题举手问老师（题目相关问题除外）。
