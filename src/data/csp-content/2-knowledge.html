一、算法复杂度基础

1.1 什么是算法复杂度

算法复杂度是衡量算法效率的核心指标，分为时间复杂度和空间复杂度：

  • 时间复杂度：算法运行所需的时间随数据规模增长的趋势，决定了算法能处理的数据上限。
  • 空间复杂度：算法运行所需的额外内存随数据规模增长的趋势，决定了算法是否会超内存限制。

影响程序实际运行时间的因素：

  1. 计算机硬件性能
  2. 输入数据的规模
  3. 算法本身的效率

竞赛中我们只关注第 3 点，即算法本身的渐进增长趋势，以此判断算法能否通过对应数据范围的测试点。

1.2 为什么用「大 O 记号」

大 O 记号（Big-O Notation）是描述复杂度的标准方式，它只保留最高阶项，忽略所有低阶项、常数系数和常数项。 原因：当数据规模 n 足够大时，最高阶项决定了算法的增长速度，常数和低阶项的影响可以忽略不计。

  • 例：执行次数为 3n² + 5n + 100，时间复杂度记为 O(n²)。
  • 例：执行次数为 1000（和 n 无关），时间复杂度记为 O(1)。

1.3 竞赛默认规则

  1. 默认讨论最坏时间复杂度：保证算法在任何输入下都能在该时间内运行完成，避免极端数据超时。

  2. 空间复杂度统计「额外辅助空间」：输入数据本身占用的空间不计入，只算算法运行时额外开辟的空间。

二、时间复杂度详解

2.1 计算三步法

  1. 找到基本语句：执行次数最多的语句，通常是最内层循环的循环体。
  2. 计算执行次数的数量级：只保留最高次幂，忽略系数和低阶项。
  3. 用大 O 记号表示：将数量级放入大 O 中。

2.2 常见复杂度阶（从快到慢）

1. 常数阶 O (1)

执行次数是固定常数，和数据规模 n 无关。

// 实例：交换两个变量
int a = 10, b = 20;
swap(a, b);

// 实例：固定次数循环
for(int i = 1; i <= 100; i++) sum += i;

易错点：只要循环次数不随 n 变化，无论循环 100 次还是 10000 次，都是 O (1)。

2. 对数阶 O (log n)

循环次数随 n 呈对数增长，典型特征是循环变量每次倍增 / 倍减。

// 实例：循环变量倍增
int cnt = 0;
for(int i = 1; i <= n; i *= 2) cnt++;

分析：i 取值为 1,2,4,8...，共执行 log₂n 次，复杂度 O (logn)。

竞赛常见 O (logn) 场景：二分查找、快速幂、辗转相除法（gcd）、堆的插入 / 删除。

3. 线性阶 O (n)

执行次数和 n 成正比，单层循环是最典型代表。

// 实例：遍历数组求和
int sum = 0;
for(int i = 1; i <= n; i++) sum += a[i];

4. 线性对数阶 O (n log n)

外层一层线性循环，内层一层对数循环，或分治算法的典型复杂度。

// 实例：嵌套循环，外层n次，内层logn次
for(int i = 1; i <= n; i++)
    for(int j = 1; j <= n; j *= 2)
        cnt++;

竞赛常见 O (nlogn) 场景：快速排序、归并排序、堆排序、sort 函数。

5. 平方阶 O (n²)

两层嵌套循环，每层执行 n 次。

// 实例：冒泡排序核心
for(int i = 1; i <= n; i++)
    for(int j = 1; j <= n - i; j++)
        if(a[j] > a[j+1]) swap(a[j], a[j+1]);

分析：总执行次数为 (n-1)+(n-2)+...+1 = n(n-1)/2，最高阶为 n²，复杂度 O (n²)。

6. 立方阶 O (n³)

三层嵌套循环，常见于 Floyd 最短路、三维 DP。

for(int k = 1; k <= n; k++)
    for(int i = 1; i <= n; i++)
        for(int j = 1; j <= n; j++)
            f[i][j] = min(f[i][j], f[i][k] + f[k][j]);

7. 指数阶 O (2ⁿ)

常见于无优化的递归搜索、暴力枚举子集。

// 实例：递归求斐波那契数列
int fib(int n) {
    if(n <= 1) return n;
    return fib(n-1) + fib(n-2);
}

分析：每层递归分支数为 2，深度约为 n，总调用次数约为 2ⁿ级别。

                            ib(4)
            /        \
       fib(3)        fib(2)
      /     \        /    \
   fib(2)  fib(1) fib(1) fib(0)
   /    \
fib(1) fib(0)

递归树分析

  • 当 n > 1 时，fib(n) 会调用 fib(n-1) 和 fib(n-2)。
  • 递归树是一棵满二叉树（直到叶子），每个内节点有两个子节点。
  • 树的高度为 n，叶子节点对应 fib(0) 和 fib(1)。
  • 总节点数（即函数调用次数）约为 2^n 量级。

更精确地，设 T(n) 为计算 fib(n) 所需的调用次数，则：

T(n)=T(n−1)+T(n−2)+1

其中 T(0) = T(1) = 1。

+1 代表的是：计算当前 fib(n) 时，除了递归调用子问题之外，自身执行的那一次加法操作所消耗的时间。

8. 阶乘阶 O (n!)

常见于全排列枚举，效率极低，仅适用于 n≤12 的极小数据。

2.3 循环结构复杂度分析规则

  1. 并列循环：复杂度相加，取最高阶。 例：一个 O (n) 循环 + 一个 O (n²) 循环，整体复杂度为 O (n²)。
  2. 嵌套循环：复杂度相乘。 例：外层 n 次，内层 m 次，整体复杂度为 O (n×m)。
  3. 条件分支：取分支中复杂度更高的作为最坏复杂度。

2.4 递归算法复杂度分析

方法一：递归树法

核心：画出递归调用树，计算每层的总工作量 × 递归深度。

以归并排序递推式 T(n) = 2T(n/2) + O(n) 为例：

  • 第 0 层（根）：1 个节点，工作量 O (n)
  • 第 1 层：2 个节点，每个工作量 O (n/2)，总工作量 O (n)
  • 第 2 层：4 个节点，每个工作量 O (n/4)，总工作量 O (n)
  • ...
  • 共 logn 层，每层总工作量都是 O (n)
  • 总复杂度：O (n × logn) = O (nlogn)

方法二：主定理（Master Theorem）（CSP-S 高频考点）

对于递推式 T(n) = a × T(n/b) + f(n)：

  • a：子问题个数
  • n/b：每个子问题的规模
  • f(n)：分解与合并子问题的工作量

三种核心情况：

  1. 若 $f(n) < n^(log_b a)$ → $T(n) = O(n^(log_b a))$
  2. 若 $f(n) = n^(log_b a)$ → $T(n) = O(n^(log_b a) × logn)$
  3. 若 $f(n) > n^(log_b a) → T(n) = O(f(n))$

典型应用：

  • 二分查找：$T(n) = T(n/2) + O(1)$ → a=1, b=2, log₂1=0 → 情况 2 → O (logn)
  • 归并排序：$T(n) = 2T(n/2) + O(n)$ → a=2, b=2, log₂2=1 → 情况 2 → O (nlogn)
  • 暴力递归斐波那契：不适用主定理（子问题规模不统一）

三、空间复杂度详解

3.1 基本概念

空间复杂度衡量算法额外占用的内存空间随数据规模的增长趋势，同样使用大 O 记号，不计入输入数据本身的空间。

3.2 常见场景分析

1. 常数空间 O (1)

只开了少量变量，没有随 n 增长的数组 / 集合。

// 实例：交换变量、单变量计数
int max_val = a[1];
for(int i = 2; i <= n; i++)
    max_val = max(max_val, a[i]);

2. 线性空间 O (n)

开辟了长度为 n 的数组、队列、栈等。

// 实例：辅助数组
int temp[100005];
for(int i = 1; i <= n; i++) temp[i] = a[i];

3. 二维空间 O (n²)

开辟了 n×n 的二维数组、二维 DP 表。

int f[1005][1005]; // 二维DP数组

3.3 递归的空间复杂度

递归的空间主要消耗在系统调用栈上，空间复杂度等于递归的最大深度。

  • 例：普通递归求阶乘，递归深度为 n → 空间复杂度 O (n)
  • 例：二分查找的递归实现，递归深度为 logn → 空间复杂度 O (logn)
  • 例：无优化斐波那契递归，最大递归深度为 n → 空间复杂度 O (n)（注意不是 O (2ⁿ)，因为调用栈是串行的，同一时间只保留一条路径）

六、高频易错点避坑指南

  1. 混淆最好和最坏复杂度 快排平均 O (nlogn)，但最坏是 O (n²)；冒泡最好 O (n)，但最坏是 O (n²)。竞赛默认按最坏情况算。
  2. 递归复杂度错判 斐波那契递归时间是 O (2ⁿ)，但空间是 O (n)，不要把时间和空间搞混。
  3. 忽略均摊复杂度 vector 的 push_back 最坏 O (n)，但均摊是 O (1)，整体 n 次 push_back 总时间是 O (n)。
  4. 排序稳定性记混 选择题高频考点，记住稳定排序：冒泡、插入、归并、基数；不稳定：选择、快排、希尔、堆。
  5. 常数项影响判断 大 O 忽略常数，但实战中 O (2n) 和 O (n) 没有数量级差距，都属于同一复杂度。

七、快速判断复杂度的实战技巧

  1. 看循环层数：1 层→O (n)，2 层→O (n²)，3 层→O (n³)（前提是每层都和 n 相关）。

  2. 看循环变量变化：每次 + 1→线性；每次 ×2→对数。

  3. 看分治特征：分成两半 + 线性合并→O (nlogn)；分成两半 + O (1) 合并→O (logn)。

  4. 看排序 / 查找：看到 “有序数组查找” 优先想 O (logn) 二分；看到排序优先想 O (nlogn)。

  5. 看数据范围：n=1e5 → 排除 O (n²)，只能是 O (n) 或 O (nlogn)。
