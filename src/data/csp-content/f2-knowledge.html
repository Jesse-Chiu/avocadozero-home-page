在信息学奥赛（OI）复赛中，输入输出（I/O）的效率和正确性直接关系到能否 AC（Accepted）。很多选手因为 I/O 写得慢导致 TLE（超时），或者因为格式控制不当导致 WA（答案错误）。

本文整理了一份复赛 I/O 详细方案，分为 cin/cout 和 scanf/printf 两个模块，重点剖析各自的注意事项，并专门针对 string 类型输入提供完整的解决方案。所有代码均采用 Allman 格式。

模块一：cin/cout 流式输入输出

在 C++ 中，cin/cout 是最符合现代编程习惯的方式，类型安全（不需要手动指定 %d 等格式符），且对 std::string 的支持极其友好。

1. 核心注意事项

  1. 必须开启 IO 加速：默认情况下 cin/cout 与 C 标准库同步，速度极慢。复赛必须加上以下两行：

    ios::sync_with_stdio(false);
cin.tie(nullptr);

    sync_with_stdio(false)：关闭 C 和 C++ 标准流的同步，大幅提速。
    cin.tie(nullptr)：解除 cin 和 cout 的绑定，避免每次输入前强制刷新输出缓冲区。

  2. 绝对不能混用 scanf/printf：开启 IO 加速后，如果混用 scanf 或 getchar()，会导致缓冲区错乱，引发玄学 WA。

  3. 换行与刷新：输出大量数据时，用 '\n' 代替 endl。endl 会强制刷新缓冲区，导致严重超时。

2. 基础用法

#include <iostream>
#include <string>
using namespace std;
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int a;
    long long b;
    double c;
    string s;
    // 输入：自动识别类型，遇空格/换行停止
    cin >> a >> b >> c >> s;
    // 输出：自动识别类型
    cout << a << " " << b << " " << c << " " << s << "\n";
    return 0;
}

3. 针对 string 的输入解决方案

cin >> 遇到空格或换行会停止，如果要读入带空格的整行字符串，必须使用 getline()。

⚠️ 致命坑点：cin >> 与 getline() 混用

cin >> n 读入数字后，缓冲区里还残留一个回车符 \n。如果紧接着用 getline(cin, s)，它会读入这个空行，导致 s 为空。必须用 cin.ignore() 或 getchar() 吃掉回车。

正确做法：

#include <iostream>
#include <string>
using namespace std;
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    string s1, s2;
    cin >> n;
    
    // 解决方案 1：忽略缓冲区直到遇到换行符
    cin.ignore(1000, '\n'); 
    // 解决方案 2：吃掉一个字符（等价于 getchar()）
    // cin.get(); 
    getline(cin, s1); // 读入整行（包含空格）
    cin >> s2;        // 读入单个单词（遇到空格停止）
    cout << s1 << "\n" << s2 << "\n";
    return 0;
}

模块二：scanf/printf 格式化输入输出

C 标准库的 I/O 方式，速度极快，且格式控制极其灵活（如保留小数、十六进制、前导零等）。适合处理纯数字、字符数组，或者对格式要求极高的题目。

1. 核心注意事项

  1. 类型必须严格匹配：

    int       -> %d
long long -> %lld   （绝不能写成 %d）
float     -> %f     （输入）
double    -> %lf    （输入），输出时 %f 和 %lf 均可
char      -> %c
char[]    -> %s

  2. 取地址符 &：scanf 中除数组名（本身代表地址）外，其他变量必须加 &。

  3. %c 的空白符吞噬：scanf("%c", &ch) 会读入空格或换行。如果前面读了数字，要读字符，必须在 %c 前加一个空格：scanf(" %c", &ch)。

  4. __int128 不支持：scanf/printf 无法直接读写 __int128，必须手写快读快写。

2. 基础用法

#include <cstdio>
using namespace std;
int main()
{
    int a;
    long long b;
    double c;
    char ch;
    char str[1005];
    // 输入：注意 double 是 %lf，long long 是 %lld
    scanf("%d %lld %lf %c %s", &a, &b, &c, &ch, str);
    // 输出：注意格式控制
    printf("%d\n", a);
    printf("%lld\n", b);
    printf("%.2f\n", c);   // 保留两位小数
    printf("%c\n", ch);
    printf("%s\n", str);
    // 进阶格式控制
    printf("%05d\n", a);   // 前导零补足5位
    printf("%x\n", a);     // 十六进制输出
    printf("%-5dEND\n", a); // 左对齐，宽度5
    return 0;
}

3. 针对 string 的输入解决方案

scanf 和 printf 完全不支持 std::string。在复赛中，如果题目涉及大量字符串操作且必须用 scanf/printf，通常需要借助 char[] 进行中转。

解决方案 A：读入单词（无空格）

#include <cstdio>
#include <string>
#include <iostream>
using namespace std;
const int MAXN = 1e5 + 10;
int main()
{
    char buf[MAXN];
    string s;
    scanf("%s", buf); // 读入 char 数组
    s = buf;          // 自动转换为 string，方便后续操作
    printf("%s\n", s.c_str()); // 输出时用 c_str() 转换回 C 风格字符串
    return 0;
}

解决方案 B：读入整行（含空格）

#include <cstdio>
#include <string>
#include <iostream>
using namespace std;
const int MAXN = 1e5 + 10;
int main()
{
    char buf[MAXN];
    string s;
    fgets(buf, sizeof(buf), stdin); // 读入整行
    s = buf;
    
    // fgets 会保留末尾的换行符，需要手动去掉
    if (!s.empty() && s.back() == '\n') 
    {
        s.pop_back();
    }
    printf("%s\n", s.c_str());
    return 0;
}

三、两种方式对比

维度cin/coutscanf/printf
速度开启 IO 加速后极快原生极快，无需额外配置
类型安全极高（自动推导）低（必须手动匹配 %d 等）
string 支持完美支持不支持，需 char[] 中转
格式控制繁琐（需 <iomanip>）极其方便（%05d、%.2f）
混用风险极容易引发玄学 WA较安全，但需注意回车符

总结与复赛策略建议

教练复赛实战建议

  1. 纯数字/基础题：推荐直接使用 scanf/printf，不需要考虑 IO 加速，且格式控制方便。

  2. 字符串/大模拟题：推荐使用 cin/cout + ios::sync_with_stdio(false)。string 的 +、==、substr、find 等操作能极大提升编码效率。

  3. 数据量极大（如 $10^6$ 级别读入）：如果使用 cin/cout，记得加 IO 加速；如果依然超时，改用 scanf 或手写快读（getchar() 版本）。

  4. 统一风格：在同一个程序中，尽量只用一种 I/O 方式。如果你决定用 cin/cout，就不要在代码里写 getchar()；如果你决定用 scanf/printf，就不要写 cin >>。

默写口诀：

cin/cout 加加速，string 处理最舒服。
scanf/printf 格式严，%lld 配 long long。
混用容易出玄学，统一风格保平安。
